# Learnings

Short, durable lessons from working on Longrun. One line each, newest last. `CLAUDE.md` holds the rules; this file holds the lessons behind them.

- Stacked PRs: merge bottom-up and delete each base branch on merge, or GitHub merges the next PR into the old branch instead of `main`. The repository now deletes head branches on merge automatically (2026-09-26).
- Library docs can lag the released package: Kysely's website still showed `Migrator` imported from `kysely`, but 0.29 moved it to `kysely/migration`. Trust a failing test and the package's own exports over examples (2026-09-26).
- Next.js 16 only logs errors thrown from `instrumentation.ts` `register()` and keeps serving; exit explicitly when startup validation fails (2026-09-26).
- GitHub OIDC subjects for repositories created after 2026-07-15 include immutable IDs (`repo:owner@ownerId/repo@repoId:...`). Build federated credential subjects from `gh api repos/OWNER/REPO` IDs, not names; the first deploy failed with AADSTS700213 (2026-09-26).
- The pipeline (Contributor on one resource group) cannot register resource providers. A new resource type in Bicep (for example `Microsoft.Network`) needs the owner to register its provider first, or the deploy fails with `MissingSubscriptionRegistration` (2026-09-26).
- App Service built-in auth answers unauthenticated non-browser requests (e.g. curl) with `401` and a `WWW-Authenticate: Bearer` challenge, and redirects browsers (`302`) straight to `login.microsoftonline.com/<tenant>/oauth2/v2.0/authorize`, not via `/.auth/login/aad`. Check both, with and without browser headers (2026-09-27).
- Deleting PostgreSQL Flexible Server firewall rules took about 5 seconds each, while creating (or re-applying) them took about a minute each. Measure an operation before designing around it (2026-09-27).
- Before designing a mechanism, look for the platform's documented, common pattern. A custom scheme for letting the pipeline call a slot behind built-in auth (and telling app tokens from users) was replaced by the standard one: anonymous `/health`, swap warm-up on `/health`, and an anonymous smoke test (2026-09-27).
- Don't mix clocks: `created_at` came from the database (`now()`) and `updated_at` from the app (`new Date()`), so with a few milliseconds of skew an update looked older than the creation. This showed up as a flaky test and was a real bug. Timestamps compared with each other come from one clock (2026-09-27).
- A `pg` pool needs an `error` listener: idle connections report database restarts and network drops through it, and without a listener Node can crash the process (node-postgres Pool docs). Found when CI on `main` failed with unhandled `57P01` errors as a test container shut down (2026-09-27).
- App Service swaps the Node.js version with the slot, but one Bicep `siteConfig` shared by both slots meant the infrastructure step would have moved production to a new runtime before staging was reviewed. The runtime is now set per slot and reaches production only through the swap (2026-09-27).
- npm `min-release-age` applies when versions are resolved (`npm install`, `npm update`), not to `npm ci` of a committed lockfile. A fix younger than the limit is installed with `--min-release-age=0` on that one command (2026-09-27).
- GitHub environment variables are printed in plain text in workflow logs, and the logs of a public repository are public. Store identifiers that should not be shown (such as the database administrator's sign-in name) as environment secrets so they are masked (2026-09-27).
- A code scanning ruleset rule for a third-party SARIF tool (zizmor) blocked merges with "waiting for results … for the commits <merge> or <head>". The action uploads SARIF for the PR's temporary merge commit, and GitHub regenerates that commit without any code change, so the rule waits for results that never come; a re-run only helps until the next regeneration. GitHub's own CodeQL default setup is not affected. zizmor now gates through a required status check (a job that fails on findings), which is tied to the head commit (2026-09-28).
- Claude Code project hooks apply immediately after `.claude/settings.json` is written, including in the session that writes it. Write guardrail files (tests, configs) before the settings file, and verify a hook with a harmless blocked command (2026-09-28).
- Claude cloud sessions ship Node 20–22, not the project's Node 24, and a PreToolUse hook that crashes lets the tool call through (only exit code 2 or a deny decision blocks). The `longrun` cloud environment installs Node 24 with a setup script, and the hook runs with `--experimental-strip-types` so Node 22 can run it (2026-09-28).
- Guardrail hooks only see the tools their matcher names. Claude cloud sessions add GitHub MCP tools (`mcp__github__*`), including merge, auto-merge, workflow triggers and file writes through the API, which bypassed a hook that matched only Edit, Write and Bash. When the agent gets a new tool surface, list its tools and decide on each (2026-09-28).
- The first G4 check in the cloud confirmed that committed `.claude/settings.json` hooks apply in cloud sessions (`CLAUDE_CODE_REMOTE=true`). It also showed that `gh` is not installed, although the cloud-environment docs say it is. GitHub access goes through the MCP tools, and `get_job_logs` can read CI logs. `list_pull_requests` reported `merged: false` for merged PRs (2026-09-28).
- In an auto-mode cloud session, the server-side safety classifier failed three times with "gave no verdict (error)" before a Bash call went through. Routines have no permission mode; watch the first routine transcripts for the same (2026-09-28).
